# SECURITY THREAT MODEL

**Status:** Greenfield blueprint. **Rule:** inspect-first means we build _with_ this model, not after.

Legend — **Detection/Logging** = how we notice and what we record (structured logs + `audit_logs`).
**Response** = automated and/or human runbook action.

---

## 1. THREAT TABLE

| Threat                       | Attack                                        | Impact                                      | Mitigation                                                                                                                      | Detection / Logging                                        | Response                                      |
| ---------------------------- | --------------------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- | --------------------------------------------- |
| **Fake sellers**             | Register, use stolen identity/payout details  | Fraudulent sales, chargebacks, reputational | Tiered KYC/verification; payout account verification; new-seller limits; tier policy                                            | Verification fails, velocity anomalies, IP/device reuse    | Suspend, freeze payouts, re-verify            |
| **Stolen software / assets** | List assets they don't own                    | IP theft, buyer loss, legal                 | Ownership challenges per asset type (`ownership_proofs`); source/repo proof; DMCA flow                                          | Ownership challenge fails; duplicate fingerprints; reports | Unlist, hold escrow, investigate              |
| **Malware**                  | Upload trojanized artifacts                   | Infect buyers, platform liability           | ClamAV + VirusTotal + sandbox scan in `scan-runner`; quarantine until pass                                                      | Scanner CRITICAL findings                                  | FAIL listing, quarantine object, notify       |
| **ZIP bombs**                | Tiny archive explodes on decompress           | DoS of scanner/worker                       | Decompress limits (ratio/depth/count/size), path-traversal rejection, time/mem caps                                             | Worker resource-ceiling breach                             | Kill job, mark ERROR/FAIL, alert              |
| **Credential theft**         | Phishing/credential stuffing/leaks            | Account takeover                            | Strong hashing (argon2id), MFA, breach-password checks, rate-limited login, session review                                      | Failed-login spikes, impossible-travel, new-device login   | Force reset, revoke sessions, notify          |
| **API key leakage**          | Secrets committed or shipped to client        | Provider abuse, data access                 | Secrets in secret manager/env; no secrets in bundles; secret scanning (Gitleaks) in CI; rotation                                | Gitleaks CI + runtime secret-scan alerts                   | Rotate keys, revoke, audit access             |
| **Payment fraud**            | Stolen cards, friendly fraud                  | Chargebacks, loss                           | Provider risk tools, velocity limits, KYC, 3DS where supported, escrow delay                                                    | Provider risk webhooks, chargeback rate monitor            | Freeze, investigate, blocklist                |
| **Bid manipulation**         | Collusion / shill bidding                     | Distorted prices, distrust                  | Self-bid block (seller≠bidder), bid history integrity, increment rules                                                          | Bid graph analysis, same-IP/device clusters                | Void bids, suspend accounts, audit            |
| **Fake bids**                | Bids from non-payers                          | Wasted inventory, delays                    | Payment obligation on win; winner-default penalty; deposit option                                                               | Payment non-completion tracking                            | Strike, restrict bidding, relist              |
| **Self-bidding**             | Seller bids own auction                       | Inflate reserve/price                       | Explicit invariant #2 (seller≠bidder) + audit                                                                                   | Audit log + bid graph                                      | Remove bid, warn/suspend                      |
| **Auction manipulation**     | Sniping abuse, timer tampering                | Unfair outcomes                             | Server-authoritative clock/timers; anti-snipe extension policy; signed server `ends_at`                                         | Client/server time deltas; bid timing patterns             | Apply anti-snipe policy, audit                |
| **Account takeover**         | Session theft, refresh-token replay           | Full account compromise                     | Rotating refresh + reuse detection (revoke family), MFA, secure token storage                                                   | Refresh reuse detection, session anomalies                 | Revoke all sessions, notify, reset            |
| **Seller impersonation**     | Copy brand/identity of another seller         | Buyer deception                             | Verified badges, name/logo review, authenticity checks                                                                          | Duplicate identity flags, reports                          | Unverify, suspend, rename                     |
| **Asset reclamation**        | Seller recovers asset post-sale               | Buyer loss                                  | Custody checklist + credential resets + transfer verification gate; escrow before release                                       | Post-release disputes, access logs                         | Escrow clawback (if held), ban, legal         |
| **Chargebacks**              | Buyer disputes captured payment               | Revenue loss, escrow mismatch               | Evidence capture, escrow buffer, clear ToS, provider cooperation                                                                | Chargeback webhook / rate monitor                          | Freeze seller proceeds, dispute workflow      |
| **Webhook replay**           | Resend captured webhook                       | Duplicate state changes                     | `UQ(provider, event_id)` dedupe; timestamp skew check; replay window                                                            | Duplicate inserts rejected; alert on attempts              | Ignore duplicates, alert on anomalies         |
| **Webhook forgery**          | Forge payment-success webhook                 | Free goods, ledger corruption               | Signature verification (spec-pending), raw body, IP allowlist where possible, S2S confirm                                       | Signature-failure logs, unsourced events                   | Reject, alert, investigate                    |
| **Double settlement**        | Same order settled twice                      | Over-payment to seller                      | Idempotent settlement worker; `SETTLED` terminal state; unique constraints                                                      | Duplicate-settlement attempts; reconciliation drift        | Halt payout, reverse via compensating entries |
| **Currency manipulation**    | Mismatch / rounding abuse                     | Money loss/gain                             | Integer minor units; currency validated end-to-end; FX as integer micro-rate; no client currency                                | Currency mismatch alerts; ledger imbalance checks          | Block txn, correct via compensating entries   |
| **Race conditions**          | Concurrent bids/checkouts/payouts             | Oversell, double-pay                        | Row locks, transactions, unique constraints, optimistic `version`, state machines                                               | Deadlock/conflict metrics; constraint violations           | Retry-safe, reconcile, audit                  |
| **Object-storage abuse**     | Direct bucket access, hotlinking, enumeration | Data leak, cost                             | Private buckets, short-lived signed URLs, presign only for authorized size/type, no public listing                              | Access logs, anomalous download/presign rates              | Revoke URLs, tighten policy, rotate creds     |
| **Malicious uploads**        | Polyglot/oversized/wrong-type files           | XSS, execution, storage abuse               | Content-type + magic-byte validation, size limits, no code execution in API, virus scan, served as download (never inline exec) | Scan findings, content-type mismatch logs                  | Quarantine, reject, alert                     |
| **SQL injection**            | Malformed input to queries                    | Data breach/tamper                          | Parameterized queries/ORM, no string concat, least-privilege DB role, WAF                                                       | Query error spikes, WAF alerts                             | Block, patch, forensic audit                  |
| **IDOR**                     | Guess object ids to access others' data       | Privacy breach, fraud                       | Ownership checks in domain for every read/write; UUIDs; never trust client ids                                                  | Access-denied logs, anomaly detection                      | Deny, alert, review                           |
| **Privilege escalation**     | Buyer/seller → admin, or lateral              | Full compromise                             | Least-privilege RBAC, admin sub-roles, MFA for admin, roles never set by client                                                 | Role-change audit logs, admin anomalies                    | Revoke, investigate, rotate                   |
| **Admin compromise**         | Stolen admin session                          | Catastrophic                                | Mandatory MFA, IP allowlist/VPN, break-glass accounts, full audit, dual control for destructive ops                             | Admin action audit, unusual admin login                    | Lock, rotate, incident response               |
| **Insider abuse**            | Employee misuses data/access                  | Fraud, privacy breach                       | Least privilege, separation of duties, dual approval for payouts/refunds, immutable audit, PII minimization                     | `audit_logs`, payout/refund anomaly reports                | Investigate, revoke, legal                    |

## 2. TOP DEFENSES APPLIED EVERYWHERE

- **Least privilege** at DB, service, and admin level.
- **Defense in depth:** edge validation **and** domain invariants **and** DB constraints.
- **Immutable audit** for every state change (`audit_logs`, append-only).
- **No secrets in code, clients, or logs.**
- **Server-authoritative** pricing, timers, and payment status (rules #9–#11).
- **Isolation** for untrusted code and heavy jobs (workers, not API).
