# Mobile — Flutter thin client

Phase 1 skeleton only. The app performs **no business logic**; it calls the API and renders results.

## First-time setup

Platform folders (`android/`, `ios/`, `web/`, …) are generated by Flutter and intentionally not
committed as hand-written scaffolding. Generate them once:

```bash
cd apps/mobile
flutter create . --project-name fa_mobile --org com.flippaafrica --platforms=android,ios
flutter pub get
```

(Adjust `--org` / `--platforms` when the final product name and targets are confirmed.)

## Layout

```
lib/
├─ main.dart                     # entrypoint
└─ src/
   ├─ app/app.dart               # MaterialApp + theme
   ├─ core/
   │  ├─ config/app_config.dart  # API base URL (--dart-define=API_BASE_URL=...)
   │  └─ network/api_client.dart # thin HTTP client
   └─ features/home/home_screen.dart
```

## Run / test / analyze

```bash
flutter pub get
flutter analyze
flutter test
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:4000
```

> Payment routing, secure storage, deep links and notifications are introduced in later phases —
> see `docs/MOBILE_ARCHITECTURE.md`. Payments must never be confirmed on-device.
